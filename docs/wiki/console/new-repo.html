Start a new repository

Turn a folder into a git repository, then put it on GitHub over HTTPS or SSH.

A git repository is a folder that git keeps track of. Starting one is a one-time job: tell git to watch the folder, decide on a branch name and a few starter files, make a first commit, and optionally put a copy on GitHub.

Nothing is overwritten. If the folder already has files, canopy leaves them as they are; it only adds a starter file that is missing.

HTTPS or SSH#

If you connect to a repository that already exists on GitHub, you choose how to reach it. Both work.

KindAddress looks likeGood to know
HTTPShttps://github.com/owner/name.gitWorks everywhere. You sign in through the browser or with a token. gh auth login sets it up.
SSHgit@github.com:owner/name.gitUses an SSH key. No password prompts once the key is added to your GitHub account. Check it with ssh -T git@github.com.
Which one canopy suggests. It follows your gh setting (gh config get git_protocol), or picks SSH if this computer already has an SSH key. You can switch later with git remote set-url origin <other address>, or in Branches, Remotes.

In canopy console#

  1. Go to the folder and run canopy, or run canopy <folder> from anywhere.
  2. With no repository there, a menu titled "No git repository in <folder>" appears. Choose Create a repository here. The other choices are Show repositories under this folder and Quit. Move with j and k and confirm with ↵, or press the letter shown next to a choice.
  3. Type a branch name (the default is main) and press ↵. Then choose a .gitignore template.
  4. At "Start with which files?" choose A README, and make the first commit, README + MIT license, and the first commit, or Nothing yet: an empty repository. canopy console only offers a README together with the first commit.
  5. At "Connect it to GitHub?" choose Create it on GitHub (when gh is signed in, then Private or Public), Connect an existing GitHub repository (type owner/name or the address, then pick HTTPS or SSH), or Skip for now. esc cancels a menu.
Skipped GitHub? You can add it later. Open Branches (4), press ] to reach Remotes, and add one there with n.

What git runs#

The first line makes the repository. The rest depend on your choices.

$ git init -b main
$ git add --all
$ git commit -m "Initial commit"
$ gh repo create acme-app --private --source=. --remote origin --push
$ git remote add origin https://github.com/owner/name.git
$ git push --progress --set-upstream origin main

The gh repo create line is for "Create it on GitHub" (--public for a public one; --push only when there is a commit). The git remote add and git push lines are for an existing repository. If origin already exists, canopy uses git remote set-url origin instead, so trying again is safe. Very old git (before 2.28) has no -b, so canopy runs git init and then git symbolic-ref HEAD refs/heads/main.

If something goes wrong#

  • "git doesn't know your name and email yet". The first commit needs an author. Run these once, with your own details, then try again: 
    $ git config --global user.name "Your Name"
$ git config --global user.email you@example.com
  • "Added the remote, but the push didn't go through". The repository probably does not exist on GitHub yet. Create it there (empty, no README), then connect again. Connecting again is safe.
  • No "Create it on GitHub" choice. gh is not installed or not signed in. Run gh auth login, or use an existing repository.
  • The push asks for a password or is denied. Check your sign-in for the kind of address you used: gh auth login for HTTPS, an SSH key for SSH. See Sync with a remote.
  • The wrong first commit. If you have not pushed, see Fix your last commit or Undo a mistake.
  • A file you did not want was committed. See Ignore files with .gitignore.
