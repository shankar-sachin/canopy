Your daily workflow

The loop you'll repeat every day in canopy console: pull, branch, edit, stage, commit, push, open a pull request.

Most days with git follow one loop: get up to date, make a branch, change things, commit in small pieces, push, and open a pull request. This page walks through it once in canopy console, and links to the page that explains each step.

The loop assumes your repository is on GitHub. If it is not, skip the pull request steps; everything else still applies.

The loop, in one line each#

  1. Pull so you start from the latest work.
  2. Branch for the change, named after it.
  3. Edit your files in your editor.
  4. Stage and commit, in small, focused commits.
  5. Push the branch.
  6. Open a pull request, and watch CI.

In canopy console#

  1. Start up to date. Run canopy in your repo and press p to pull. Home tells you if you are behind: "3 new commit(s) on the remote. Press p to pull."
  2. Make a branch. Press 4 for Branches, then n, name it after the change (spaces become hyphens) and press ↵. canopy switches to it. See Branches, merging and rebasing.
  3. Edit your files in your editor. canopy notices changes on its own; ⌃R refreshes right away.
  4. Review and stage. On Changes (2), press space to stage a file, or ↵ to open the diff and stage only some lines.
  5. Commit. Press c, write a summary, press ↵. Repeat steps 3 to 5 as you go. See Write good commits.
  6. Push. Press P. The first push of a new branch also sets it to track the remote. If canopy says the branch has diverged, see Sync with a remote.
  7. Open a pull request. Press 8 for Pull requests, then n. The branch must be pushed first. See Working with GitHub.
  8. Watch CI. Press 0 for Actions. Home's GitHub card shows check results too.

Home's Next steps list suggests what to do from wherever you are, with the key for each. Teach mode is on by default, so the footer shows the git command behind every step; T toggles it.

What git runs#

$ git pull
$ git switch -c fix-login-timeout
$ git add -- src/login.rs
$ git commit -m "Raise the login timeout to 30 seconds"
$ git push --set-upstream origin fix-login-timeout
$ gh pr create --title "Raise the login timeout" --body "..." --base main

The pull request is made by the GitHub CLI, gh, which canopy uses for everything on GitHub.

Tips#

  • Need to switch tasks but not ready to commit? Put the work aside with the stash. See Put work aside with the stash.
  • Committed too early? Amend the last commit. See Fix your last commit.
  • Commit often and small. Small commits are easier to review, and easier to undo.

If something goes wrong#

  • Pull stops with a conflict. Follow Resolve a merge conflict.
  • You worked on main by mistake. Make a branch from where you are (4 then n) before you push; your commits come with you. Then move main back with Undo a mistake.
  • You committed the wrong thing. Press z to undo it. canopy asks first, and your changes come back as staged changes.
  • Push is refused. The remote has moved. See Sync with a remote.
  • New PR says to push first. A pull request needs the branch on GitHub. Press P, then try again.
