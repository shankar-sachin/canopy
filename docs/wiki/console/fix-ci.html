Fix a failing CI run

Find out why CI failed, fix it (or re-run it), and get back to green.

CI (continuous integration) is a set of checks GitHub runs every time you push: tests, a build, a linter. A red cross means one of them failed. The reason is in the run's log, which is long and hard to read.

canopy console reads the log for you and shows the failed step first. It can also re-run a failed run, or write a prompt from the failure and open your AI assistant with it. You need gh signed in (gh auth login).

In canopy console#

  1. Press 0 for Actions. Press f to cycle the filter if you cannot see the run you want.
  2. Select the failed run. Press e for its details, or L for the full failed log, with the failed jobs first.
  3. Press A to fix it with AI. It writes the prompt and opens your assistant in a new terminal tab (a new window if a tab is not possible).
  4. Read what the assistant suggests, then make the change. The assistant is told not to commit or push, so those stay under your control.
  5. Press R to re-run only the failed jobs, useful when the failure was a flaky test or a network hiccup and you changed nothing. Both A and R only work on failed runs.
  6. Press o to open the run in your browser.

Once you have a fix, commit it with c and push with P. GitHub starts a new run on its own.

Choose the assistant#

Two settings in config.toml control this. ai picks the assistant: auto (the first of Claude Code and Codex that is installed), claude, codex, off, or your own command, where {prompt} stands for the prompt text. ai_open picks where it opens: tab (the default), window, or here, which runs it in this terminal and puts canopy aside until it exits. See Configuration.

What the assistant is given#

The prompt is a file, .git/canopy/fix-ci.md. It lives inside the .git folder, so it is never committed. It holds:

  • the failed job and step, and GitHub's summary of the run,
  • the last 200 lines of the cleaned-up log,
  • instructions: find the cause, make the smallest fix, run the checks, explain what you did, and do not commit or push.

The assistant starts with a short message that points at this file. The prompt goes to the assistant you chose, and through it to that service, so do not use this on a repository whose logs must not leave your machine.

What git runs#

Runs are read with gh. Nothing here changes your repository until you commit yourself.

$ gh run view <id> --json jobs
$ gh run view <id>
$ gh run view <id> --log-failed
$ gh run rerun <id> --failed

The first three build the failure summary and the prompt, and --log-failed is also what L shows. The last one is the re-run key, R.

If something goes wrong#

  • "No AI assistant set up". Install Claude Code or Codex, or set ai = "your command" in the config. See Configuration.
  • On a Mac, the assistant does not open. canopy needs permission to open Terminal windows. If you said no, allow it in System Settings, Privacy & Security, Automation, then press A again. The prompt file is already saved in .git/canopy/fix-ci.md, so you can also start your assistant yourself and point it there.
  • "Pick a failed run: A writes a fix-it prompt from its error". The selected run did not fail. Select a red one.
  • "Only failed runs can be re-run from here". Same reason for R. To run a passing run again, do it on GitHub.
  • The re-run fails again. The failure is real. Read the log, fix the code, then push.
  • It passes on your computer and fails on GitHub. The run uses a clean machine. Look for a missing file, a version difference, or a file your .gitignore hides. See Ignore files with .gitignore.
  • You pushed a fix that made things worse. See Undo a mistake.
