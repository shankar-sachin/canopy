Undo a mistake

Take back a commit, a reset, a merge or a checkout, and get back work you thought was lost.

Git rarely loses anything. A commit, a merge, a reset or a checkout can nearly always be taken back, because git remembers where your branch used to point. The one thing it cannot bring back is edits you never committed and then threw away.

The quick way is z. It looks at the last thing that moved your branch, tells you exactly what it will do, and only does it when you agree. For anything older, use a reset or the Reflog.

In canopy console#

Undo the last action#

  1. Press z from any screen. A box Undo last action? shows the last action and what will happen (or Undo checkout? if you last switched branch).
  2. Press ↵ to confirm, or esc to cancel. Nothing changes until you confirm.

What z does depends on what you did last:

Last actionUndo does this
A commit (or an amend)Moves the branch back one commit. The commit's changes come back as staged changes, ready to fix and commit again.
A checkout (switching branch)Switches back to the branch you came from.
A merge, cherry-pick, revert, reset or rebaseMoves the branch back to where it was before, and keeps your uncommitted changes. A whole rebase counts as one action.

Undo is built from git's reflog, so it can't take back a push, a discard or a dropped stash.

Go back further: reset#

  1. Open History (3) and select the commit you want to go back to.
  2. Press r. The box Reset current branch to … asks how to treat the changes in the commits that leave the branch. Mixed is highlighted.
  3. Press s for Soft (their changes stay staged), m for Mixed (their changes stay, unstaged) or h for Hard (their changes and your uncommitted work are thrown away). You can also move with j and k and press ↵.

After a Hard reset, z brings the commits back, but uncommitted edits are gone for good.

Undo a commit you already shared: revert#

If the commit is on the remote, don't rewrite history. Select it on History and press t. That adds a new commit that undoes its changes and keeps the old one in the history, so nobody else's copy breaks.

Throw away uncommitted edits on purpose#

On Changes (2), select an unstaged file and press d. canopy shows what will be lost and asks first: a new file is deleted, and for a changed file your unstaged edits are thrown away. The box says This cannot be undone, and it is right, because git never saved those edits. If the file is staged, unstage it first with space.

Get back something that seems gone#

The Reflog screen lists everywhere your branch has been, including commits no branch points to any more, such as ones you reset away or an old version of a commit you amended.

  1. Open Reflog (7) and find the entry from before the mistake. Press ↵ to look at that commit.
  2. Press r and choose m (Mixed) to move your branch there and keep your files as they are, or h (Hard) to make your files match it too.

What git runs#

Undo and the reset keys are git commands on your branch. Undo uses --soft after a commit and --keep otherwise, and falls back to --mixed if --keep refuses because your edits touch files that differ.

$ git reset --soft <previous commit>
$ git reset --keep <previous commit>
$ git switch <branch you came from>
$ git reset --soft|--mixed|--hard <commit>
$ git revert --no-edit <commit>
$ git restore --worktree -- <file>
$ git clean -f -d -- <new file>

The last two are Discard: restore for a changed file, clean to delete a new one.

The difference between reset and revert: reset moves the branch back, so the later commits leave it. revert keeps them and adds a commit that cancels one out.

If something goes wrong#

  • "Nothing to undo". The reflog has no earlier step for this repository. Use reset instead.
  • You chose Hard by mistake. The commits come back (press z, or find the old one in Reflog and reset to it), but uncommitted edits are gone for good.
  • You pushed already. Undo and reset only change your copy. If others may have pulled the commit, use revert. If you reset a pushed branch, pushing the result needs a force push, which replaces the remote copy (the push box offers Force push with lease when your branch and the remote have diverged). Do that only on a branch nobody else uses.
  • Undo did more than you expected. It always shows the last action first. If it was not the one you meant, press esc and reset to the exact commit instead.
  • "Unstage the file first (space), then discard". Discard only works on unstaged files. Press space on the file, then d.
