Working with GitHub

Connect canopy console to GitHub, then handle pull requests, CI runs and notifications without opening a browser.

canopy console talks to GitHub through the GitHub CLI (gh). Once you are logged in, pull requests, issues, CI runs, releases and notifications each get a tab, and you never need a browser for the everyday loop.

This page covers the whole loop: connect, open a pull request, check CI, merge. For the details of reviewing and CI, see the two recipes it links to.

Connect to GitHub#

Run gh auth login once in any terminal and follow the prompts. canopy checks with gh auth status; if you are not logged in, the GitHub tabs tell you so. Nothing else is stored by canopy. If the folder is not on GitHub yet, see Start a new repository.

In canopy console#

  1. Push your branch. Press P. A pull request needs a branch that is not the default branch and that has an upstream; otherwise canopy says "Push this branch first (P), then open the pull request".
  2. Open the PR. Press 8 for the PRs tab, then n. The form is headed "New pull request: your-branch → base". Fill in the title and description, then submit.
  3. Watch CI. Press 0 for Actions. Runs show as passing, failing or in progress. f filters them.
  4. If a run failed: select it and press e for details or L for the full log. R re-runs only the failed jobs. A asks your AI assistant to fix it. See Fix a failing CI run.
  5. Review. On the PRs tab, f cycles the filter, ↵ opens a PR and D toggles its diff. r opens the review menu: a approve, c comment, x request changes. C adds a plain comment. space checks the PR's branch out locally. See Review a pull request.
  6. Merge. Press M: m merge commit, s squash, r rebase. If checks are failing, the menu title says "! checks are failing". Then press p on your default branch to bring the merge down.

Issues, releases and notifications#

  • Issues (9): n opens a new one, C comments, X closes or reopens.
  • Releases: on the Actions tab, ] switches to Releases, where n writes a new one. See Tag a version and publish a release.
  • Notifications (⌥N): ↵ opens one in the browser, m marks it read, M marks all read, u switches between unread and all.

Every key for these tabs is in Keyboard shortcuts.

What runs underneath#

Each action is one gh command; canopy only fills in the details.

$ gh auth status
$ gh pr list
$ gh pr create --title "Add word counter" --body "..." --base main
$ gh pr checkout 42
$ gh pr review 42 --approve
$ gh pr merge 42 --squash --delete-branch
$ gh issue create --title "Crash on empty file"
$ gh run list
$ gh run rerun 123456 --failed
$ gh release create v1.2.0

If something goes wrong#

  • The GitHub tabs say you are not logged in. Run gh auth login in a terminal, then press ⌃R to refresh.
  • "gh" is not found. The GitHub CLI is not installed. Install it from cli.github.com, then reopen canopy.
  • You cannot open a PR. You are on the default branch, or the branch has no upstream. Make a branch (Branches, merging and rebasing) and push it with P.
  • Push is denied. Your GitHub account lacks write access to that repository. Fork it, or ask the owner.
  • You merged the wrong way. A merge on GitHub cannot be undone from canopy. Revert the merge commit with a new commit, or see Undo a mistake.
  • The PR list is empty but you expect one. Press f to change the filter: it may be showing only one kind.
