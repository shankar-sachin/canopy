Put work aside with the stash

Save half-done changes without committing them, switch to something else, and bring them back later.

The stash is a shelf for half-done work. You have changes you are not ready to commit, but you need a clean folder right now: to switch branches, pull, or fix something urgent. Stash them, do the other thing, then bring them back.

A stash is stored inside your repository (not sent to GitHub), and you can keep several. Each one is named stash@{0}, stash@{1} and so on, newest first.

In canopy console#

Put changes aside#

  1. Press S from any screen.
  2. Type a message if you want one, so you recognise the stash later. New (untracked) files are always included.
  3. Press ↵. Your files go back to the last commit and the stash is saved. (With nothing changed, canopy says Nothing to stash.)

Bring it back#

  1. Open the Stash screen (5). Move with j and k; ↵ shows what is inside.
  2. Press g to pop it (bring the changes back and remove the stash), or space to apply it (bring them back and keep the stash, handy to try the same changes on another branch).
  3. Press d to drop a stash you don't need any more. canopy shows Drop stash? and asks first.

What git runs#

The stash commands are plain git. --include-untracked is what puts brand-new files aside too.

$ git stash push --include-untracked -m "half-done refactor"
$ git stash apply stash@{0}
$ git stash pop stash@{0}
$ git stash drop stash@{0}

If something goes wrong#

  • Apply or pop stops with an error about local changes. Git won't bring a stash back over files you have changed since. Commit those changes or stash them first, then try again. Nothing was lost; the stash is still in the list.
  • Pop leaves conflicts. The stash and your current files changed the same lines. The stash is kept, so nothing is lost. Fix the files on Changes and drop the stash when you are done. See Resolve a merge conflict.
  • The stash is on the wrong branch. Stashes are not tied to a branch. Switch to the right branch and apply it there.
  • You dropped one by mistake. z doesn't cover dropped stashes. Git usually still holds the content for a while, but finding it takes advanced git commands, so read the name in the confirmation box before you press ↵.
  • You popped and want it back on the shelf. Stash again with S. Undo a mistake covers commits and resets, not stashes.
