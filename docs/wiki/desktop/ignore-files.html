Ignore files with .gitignore

Keep build output, secrets and editor clutter out of git, and stop tracking a file you committed by mistake.

Some files should never be in git: build output, downloaded packages such as node_modules, secrets like .env, and clutter your computer makes (.DS_Store). A file named .gitignore at the top of your project lists what git should leave alone. Ignored files stop showing up in your changes and can't be staged by accident.

Ignoring only works for files git is not tracking yet. If you already committed a file, ignoring it is not enough: see Stop tracking a file you already committed.

In canopy desktop#

canopy desktop has no "ignore this file" button. What it does offer:

  1. For a new repository: when you set one up (see Start a new repository), the .gitignore drop-down can start you with a ready-made list for Rust, Node / JavaScript, Python or macOS only (.DS_Store). The default is No .gitignore.
  2. For an existing repository: open the project's .gitignore in any text editor (create it in the top folder of the project if it doesn't exist) and add one pattern per line, for example node_modules/ or .env.
  3. Back in canopy, open Changes. The ignored files are gone from the list, and .gitignore itself shows up as a change. Stage it and commit it so your teammates get the same list.

What git runs#

Adding to .gitignore is a text edit, not a git command, and git reads the file on its own the next time it looks at your files. The only command involved is the one that stops tracking a file you committed earlier, which you run yourself (see below):

$ git rm --cached -- path/to/file

Patterns you'll use#

LineIgnores
.envAny file called .env, in any folder
/targetOnly target at the top of the project (a leading / means "from the top")
node_modules/Any folder called node_modules (a trailing / means folder)
*.logEvery file ending in .log
!keep.logAn exception: don't ignore this one
# a noteA comment

Stop tracking a file you already committed#

If a file was committed before you ignored it, git keeps tracking it, and .gitignore has no effect on it. canopy desktop can't do this step, so you use a terminal:

  1. Add the file to .gitignore as above.
  2. In a terminal, inside the repository, run git rm --cached path/to/file (use git rm -r --cached folder for a folder). This makes git forget the file without deleting it from your disk.
  3. Back in canopy, the deletion shows up on Changes as a staged change. Commit it. From then on the file stays on your disk but out of git.
Secrets stay in history. This stops tracking the file from now on, but earlier commits still contain it. If it held a password or a key, treat that secret as leaked and change it.

Ignore files on every project#

For clutter that comes from your own computer and editor, rather than the project, a global ignore file saves editing every repository. In a terminal:

$ git config --global core.excludesFile ~/.gitignore_global

Then list patterns such as .DS_Store in ~/.gitignore_global. This is plain git, not something canopy sets up for you.

If something goes wrong#

  • The file still shows up after you ignored it. It is already tracked. Follow Stop tracking a file you already committed.
  • A pattern ignores too much. Make it more specific (start with / to anchor it at the top of the project) or add an exception with !. Then look at Changes to see what came back.
  • You need to commit an ignored file once. Ignored files don't appear on Changes, so canopy can't stage them. Remove or narrow its pattern first, or run git add -f file in a terminal.
  • You added a wrong line to .gitignore. The undo arrow doesn't cover edits to files. Open .gitignore in your editor and delete the line, or use Discard… on Changes to throw away all your edits to it.
