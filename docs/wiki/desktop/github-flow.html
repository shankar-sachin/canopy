Working with GitHub

Connect canopy desktop to GitHub, then handle pull requests, CI runs and notifications without opening a browser.

canopy desktop handles pull requests, issues, CI runs and notifications without a browser tab. It does this through the official GitHub CLI, gh, using your own login: canopy has no separate account and stores no token.

You connect once. After that the GitHub pages work, and Home shows a GitHub card for the branch you are on.

In canopy desktop#

Connect GitHub#

canopy never installs anything for you. If gh is missing or you are logged out, each GitHub page shows a card that says exactly what to run. To do it yourself:

$ brew install gh
$ gh auth login

On Windows use winget install --id GitHub.cli -e, and on Linux see cli.github.com. Follow the prompts of gh auth login in a terminal, then come back and press Try again on the card.

The card saysWhat it means
Connect GitHubgh is not installed. Install it, then log in.
Log in to GitHubgh is installed but not logged in. Run gh auth login.
Not a GitHub repositoryThis repository has no GitHub remote, so there is nothing to show. See Start a new repository to add one. Everything on the git pages still works.

The GitHub pages#

The sidebar's GitHub group holds Pull requests, Issues, Actions and Notifications, reached with ⌘6 to ⌘9 (Ctrl+6 to Ctrl+9 on Windows and Linux).

Pull requests#

  1. Find one. Filter by Open, Mine, To review or All. Select a pull request to see its description, checks, reviews and comments.
  2. Create one. Push your branch first, then press New PR…. The title is filled in from your last commit; add a description, optionally set Into to another base branch, and tick Open as a draft if it is not ready. Press Create pull request. If the branch has not been pushed, canopy says "Push <branch> first, then open a pull request for it."
  3. Work on one. The buttons are View in GitHub, Check out (to run it locally), Comment…, Review…, Close… and Merge…. A banner warns when the pull request conflicts with its base branch.
  4. Review. Review… offers Approve, Request changes or Comment only. A comment is required unless you approve. Press Submit review.
  5. Merge. Merge… asks how: Squash and merge (one commit) (the default), Create a merge commit or Rebase and merge. Delete <branch> afterwards is ticked by default. Press Merge.

Issues#

  1. Filter by Open, Assigned to me or All.
  2. New issue… takes a title and a description. An issue can be commented on, closed and reopened.

Actions#

  1. The tabs are This branch and All branches. Select a run to see its jobs.
  2. For a failed run, Details shows the log and Re-run failed jobs tries again. Fix with your AI assistant hands it the failure; set an assistant up in Settings. See Fix a failing CI run.

Notifications#

  1. Switch between All repositories and This repository. Tick Read too to include ones you have read.
  2. Press Mark all read to clear the list; canopy asks first.
  3. Select a notification for its buttons: Open in canopy, View in GitHub and Mark as read.

The Home GitHub card#

On Home, the GitHub card shows the pull request for your current branch (its number, title, review state and how many checks passed), how many pull requests are waiting for your review, and how many notifications are unread. Click a count to jump to that list. If your latest CI run failed, a red banner offers Details, View in GitHub and Fix with your assistant.

What git runs#

These are gh commands rather than git. canopy runs them for you, and shows them when Show git commands is on in Settings.

$ gh auth status
$ gh pr list
$ gh pr checkout 12
$ gh pr create --title "Add top_words" --body "..." --base main --draft
$ gh pr review 12 --approve
$ gh pr merge 12 --squash --delete-branch
$ gh issue create --title "Crash on an empty file" --body "..."
$ gh run list
$ gh run rerun 101 --failed

--base and --draft are added only when you fill in Into or tick Open as a draft. --delete-branch is added only when Delete <branch> afterwards is ticked.

If something goes wrong#

  • The GitHub pages ask you to connect. Run gh auth login in a terminal and press Try again. To check, run gh auth status.
  • "Not a GitHub repository". The repository has no GitHub remote yet. See Start a new repository.
  • You cannot open a pull request. The branch must be pushed first; see Sync with a remote. On your default branch, make a branch first.
  • Merge is blocked or checks are failing. Look at the checks, then see Fix a failing CI run.
  • You merged the wrong way, or too early. A merge on GitHub cannot be undone from canopy. Revert the commit from History, and open a new pull request.
  • Nothing shows up. Check that gh auth status shows you logged in and that your account can see the repository.
