Branches, merging and rebasing

What branches are for, the two ways to combine them, and what to do when they collide.

A branch is a movable name for a commit. When you commit, the branch you are on moves forward. That is all it is, which is why branches are cheap: make one for every change, and main stays working while you experiment.

This page covers making, switching, renaming and deleting branches, bringing two branches together with a merge or a rebase, and what to do when they collide.

In canopy desktop#

Merge or rebase?#

Both bring one branch's commits into another. They differ in the history they leave.

MergeRebase
What it doesJoins the two lines with a merge commit that has two parents.Replays your commits on top of the other branch, as if you had started from its latest commit.
HistoryKeeps what really happened, including the fork.A straight line, no merge commit.
Your commitsUnchanged.Rewritten: they get new hashes.
Best forBringing a finished branch into main, or any commits others already have.Tidying your own unshared branch before you open a pull request.
The one rule. Never rebase commits other people have already pulled. Rebasing rewrites them, and their copies will no longer match yours.

Work with branches#

Open Branches (⌘4 (Ctrl+4 on Windows and Linux)). Its tabs are Local, Remote, Tags and Remotes, each with a count. A local branch shows ↑N or ↓N when it is ahead of or behind its upstream.

  1. Create. Press New branch…, type a name such as feature/my-idea, and press Create branch. It starts from where you are now. Leave Switch to it ticked to move onto it straight away.
  2. Switch. Press Check out on a branch. If you have changes that the switch would overwrite, git refuses and says so; commit or stash them first (see Put work aside with the stash).
  3. Merge. Check out the branch that should receive the changes, then press Merge into <branch> on the other one and confirm Merge.
  4. Rebase. Check out your own branch, then press Rebase onto on the branch you want to build on and confirm Rebase. The dialog reminds you not to rebase commits others already pulled.
  5. Rename. Press Rename, edit the name and press Rename. The branch you are on shows only Rename.
  6. Delete. Press Delete. The dialog offers Delete and Force delete. If the branch has commits that are not merged anywhere, plain delete is refused; force delete removes it anyway, and those commits can then only be found through the reflog.
  7. Remote branches. On the Remote tab, Check out makes a local branch that tracks it, and Delete on remote removes it from the server for everyone, after a confirm.

A branch's upstream is set by its first Push; there is no separate button for it.

What git runs#

$ git switch -c feature/my-idea
$ git switch main
$ git merge --no-edit feature/my-idea
$ git rebase main
$ git branch -m old-name new-name
$ git branch -d feature/my-idea
$ git branch -D feature/my-idea
$ git push origin --delete feature/my-idea

With Switch to it unticked, canopy runs git branch feature/my-idea instead of git switch -c. Check out on a remote branch runs git switch --track origin/feature/my-idea. -d refuses to delete unmerged work; -D does not.

If something goes wrong#

  • The merge or rebase stops and a banner says there is a conflict. Both branches changed the same lines. Follow Resolve a merge conflict, or press Abort on the banner to go back to where you were.
  • Git refuses to switch branches. You have changes it would overwrite. Commit them, or stash them (Put work aside with the stash), and switch again.
  • Git refuses to delete a branch. It has commits that are not merged anywhere. Merge it first, or use Force delete only if you are sure you do not need them.
  • You deleted a branch you needed. Its commits stay in the reflog for a while. See Undo a mistake.
  • You merged or rebased the wrong way. Undo it with ⌘Z (Ctrl+Z on Windows and Linux).
  • After a rebase, push is refused or opens a dialog. Your commits were rewritten, so the branch has diverged from the remote. See Sync with a remote.
