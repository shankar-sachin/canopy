Fix a failing CI run

Find out why CI failed, fix it (or re-run it), and get back to green.

CI (continuous integration) is the robot on GitHub that builds and tests your code every time you push. When a run fails, the commit gets a red mark, and the cause is buried in a long log.

canopy desktop watches the latest run for the commit you are on. If it failed, Home shows a banner with the short reason. From there you can read the failed part of the log, re-run the failed jobs, or hand the error to an AI assistant that opens in a terminal window. You need GitHub connected first (see Working with GitHub).

In canopy desktop#

  1. Open Home. If the latest run for your current commit on this branch failed, a banner says "canopy found an error in your latest commit", with the headline of the error and the workflow name. canopy checks again whenever your branch moves, and every minute.
  2. Click Details on the banner. A window titled "What went wrong" shows the same text an assistant would get, and the file it is saved in. Copy copies it, Open in editor opens it, and View in GitHub opens the run in your browser.
  3. To see every run, open Actions in the sidebar. The tabs are This branch and All branches. Each row shows the workflow, the branch, what triggered it and its age.
  4. Click a run. The jobs are listed with their steps, and failed ones start open. The end of the failed log is shown under "End of the failed log".
  5. Fix it yourself, or click Fix with your assistant (its name is on the button, for example Fix with Claude Code). canopy saves a prompt file and opens the assistant in a new terminal window. The toast says where it opened.
  6. Review what the assistant changed on the Changes page. Commit and push the fix (see Write good commits). A new run starts on its own.
  7. If the failure was a fluke (a network hiccup, a slow test), click Re-run failed jobs on the run's page instead of pushing anything.

What git runs#

These commands go through the gh command line tool. <id> is the run's number.

$ gh run view <id> --json jobs
$ gh run view <id> --log-failed
$ gh run rerun <id> --failed

Committing and pushing your fix are ordinary git commit and git push commands, run from the Changes page.

Choosing the AI assistant#

In Settings, the "AI assistant" row has these choices.

ChoiceWhat it does
AutoUses whichever assistant canopy finds on your computer.
Claude Code, CodexAlways uses that one.
Custom command…Runs your own command in a "Command" field. Put {prompt} where the prompt should go, for example aider --message {prompt}. Without {prompt}, the prompt is added at the end.
OffNo assistant. The Fix button becomes "Set up an AI assistant".

What the assistant is given#

canopy writes a prompt to .git/canopy/fix-ci.md inside your repository. It holds the failed job and step, GitHub's summary of the failure, and the last 200 lines of the failed log with the noise cleaned out. It ends with the instruction not to commit or push, so you review the change first.

Your code may leave your computer. The assistant sends what it reads to its own service. The log can contain file names, paths and messages from your project. Read Details before you click Fix with if that matters for this repository.

If something goes wrong#

  • "No AI assistant set up yet". Nothing is installed or chosen. Install Claude Code or Codex, or pick or type one in Settings, which the button opens for you.
  • "Couldn't open a terminal. The prompt is saved in …". Open the saved file and paste it into your assistant yourself.
  • "macOS didn't let canopy open …". Allow it in System Settings, Privacy & Security, Automation: turn on Terminal (or iTerm) under canopy. Then try again. The prompt file is saved either way.
  • The banner never appears. It only shows when the latest run for exactly this commit, on this branch, failed. If you have pushed a newer commit, the run may still be going. It also needs GitHub connected.
  • It passes on your computer and fails on GitHub. A file that exists only on your machine, such as an ignored config or build output, is the usual cause. Check what git tracks (see Ignore files with .gitignore).
  • The re-run fails again. It was a real failure, not a fluke. Read the failed log and fix the cause.
  • You pushed a bad fix. Take the commit back with Undo a mistake, then push again.
