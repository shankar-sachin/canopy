Your daily workflow

The loop you'll repeat every day in canopy desktop: pull, branch, edit, stage, commit, push, open a pull request.

Most days with git follow one loop: get up to date, make a branch, change things, commit in small pieces, push, and open a pull request. This page walks through it once in canopy desktop, and links to the page that explains each step.

The loop assumes your repository is on GitHub. If it is not, skip the pull request steps; everything else still applies.

The loop, in one line each#

  1. Pull so you start from the latest work.
  2. Branch for the change, named after it.
  3. Edit your files in your editor.
  4. Stage and commit, in small, focused commits.
  5. Push the branch.
  6. Open a pull request, and watch CI.

In canopy desktop#

  1. Start up to date. Open your repository (⌘O (Ctrl+O on Windows and Linux), or pick it from the Recent list) and press Pull in the top bar. Home shows ↑N and ↓N pills for how many commits you are ahead of or behind the remote. Fetch updates those numbers without changing your files.
  2. Make a branch. On Branches, press New branch…, name it after the change, like fix-login-timeout, and press Create branch. With Switch to it ticked (the default), canopy moves onto it. See Branches, merging and rebasing.
  3. Edit your files in your editor as usual. canopy notices changes on its own (Settings, General, Refresh); ⌘R (Ctrl+R on Windows and Linux) refreshes by hand.
  4. Review and stage. On Changes, read each diff. Click + to stage a file, or pick lines and press Stage N lines to stage only some.
  5. Commit. Write a Summary and press Commit N files, or ⌘↵ (Ctrl+Enter on Windows and Linux). Repeat steps 3 to 5 as you go. See Write good commits.
  6. Push. Press Push. The first push of a new branch also sets it to follow the remote, so later pushes and pulls need nothing more. If a dialog says the branch has diverged, see Sync with a remote.
  7. Open a pull request. On Pull requests, press New PR…. The title is filled in from your last commit; add a description of what changed and why, and press Create pull request. Tick Open as a draft if it is not ready for review.
  8. Watch CI. Actions lists the runs for your branch, and Home's GitHub card shows whether checks pass. See Working with GitHub.

Home's Next steps card suggests the next move from wherever you are, with a button that does it: Open Changes when files have changed, Push when you have commits to send, Pull when you are behind.

What git runs#

$ git pull
$ git switch -c fix-login-timeout
$ git add -- src/login.rs
$ git commit -m "Raise the login timeout to 30 seconds"
$ git push --set-upstream origin fix-login-timeout
$ gh pr create --title "Raise the login timeout" --body "..."

canopy adds --progress to fetch, pull and push so it can show a progress bar. The pull request is made by the GitHub CLI, gh, which canopy uses for everything on GitHub. Turn on Show git commands in Settings to see each command as it runs.

Tips#

  • Need to switch tasks but not ready to commit? Put the work aside with the stash. See Put work aside with the stash.
  • Committed too early? Amend the last commit. See Fix your last commit.
  • Commit often and small. Small commits are easier to review, and easier to undo.

If something goes wrong#

  • Pull stops with a conflict. Both sides changed the same lines. Follow Resolve a merge conflict.
  • You worked on main by mistake. Make a branch from where you are before you push; your commits come with you. Then move main back; see Undo a mistake.
  • You committed the wrong thing. Press the undo button in the top bar, or ⌘Z (Ctrl+Z on Windows and Linux). Your changes come back as staged files.
  • Push says "Nothing to push: pull first." The remote has moved and you have nothing new. Press Pull. If you have new commits too, canopy opens the diverged dialog instead; see Sync with a remote.
  • New PR says "Push <branch> first, then open a pull request for it." A pull request needs the branch on GitHub. Press Push, then try again.
