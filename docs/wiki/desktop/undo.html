Undo a mistake

Take back a commit, a reset, a merge or a checkout, and get back work you thought was lost.

Git rarely loses anything. A commit, a merge, a reset or a checkout can nearly always be taken back, because git remembers where your branch used to point. The one thing it cannot bring back is edits you never committed and then threw away.

The quick way is the undo arrow in the top bar. It looks at the last thing that moved your branch, tells you exactly what it will do, and only does it when you agree. For anything older, use a reset.

In canopy desktop#

  1. Click the undo arrow in the top bar, next to the refresh button (or press ⌘Z, Ctrl+Z on Windows and Linux, while you are not typing in a text box).
  2. A dialog, Undo the last action?, shows the last action and what will happen. Click Undo to go ahead or Cancel to leave everything alone.

After a commit, a merge or a similar action, the notice at the bottom also reminds you: Undo with ⌘Z if that wasn't what you meant. What Undo does depends on what you did last:

Last actionUndo does this
A commit (or an amend)Moves the branch back one step. The commit's changes come back as staged changes, ready to fix and commit again.
A checkout (switching branch)Switches back to the branch you came from.
Anything else that moved the branch, such as a merge, pull, cherry-pick, revert, reset or rebaseMoves the branch back to where it was before, and keeps your uncommitted changes. A whole rebase counts as one action.

Undo is built from git's reflog (its private diary of where your branch has been), so it can't take back a push, a discard or a dropped stash. If it has nothing to go back to, you see Nothing to undo yet.

Go back further: reset#

  1. Open History in the sidebar and click the commit you want to go back to.
  2. Click Reset to here… in the details on the right. The dialog, Reset main to …?, asks how to treat the changes in the commits that leave the branch.
  3. Choose Soft (their changes stay staged), Mixed (their changes stay, unstaged) or Hard (their changes and your uncommitted work are thrown away). Hard asks once more, under Throw away uncommitted work?, because that part can't be recovered.

The commits after the one you chose leave the branch, but Undo can bring them back right afterwards. After a Hard reset the commits can come back that way, but the uncommitted edits that were thrown away cannot.

Undo a commit you already shared: revert#

If the commit is on the remote, don't rewrite history. Select it on History and click Revert, then Revert again in the dialog. That adds a new commit that undoes its changes and keeps the old one in the history, so nobody else's copy breaks.

Throw away uncommitted edits on purpose#

On Changes, select the file and click Discard…. The dialog, Discard changes?, says what will be lost. A new file is deleted (the button says Delete file); for a changed file, your unstaged edits are thrown away and staged changes stay. Undo cannot bring this back, because git never saved those edits.

What git runs#

Undo and the reset buttons are git commands on your branch. After a commit, Undo uses --soft. For everything else it uses --keep, and falls back to --mixed if --keep refuses because your edits touch files that differ.

$ git reset --soft <previous commit>
$ git reset --keep <previous commit>
$ git switch <branch you came from>
$ git reset --soft|--mixed|--hard <commit>
$ git revert --no-edit <commit>
$ git restore --worktree -- <file>
$ git clean -f -d -- <new file>

The last two are Discard: restore for a changed file, clean to delete a new one.

The difference between reset and revert: reset moves the branch back, so the later commits leave it. revert keeps them and adds a commit that cancels one out.

If something goes wrong#

  • "Nothing to undo yet." There is no earlier step recorded for this repository. Use Reset to here… on History instead.
  • You chose Hard by mistake. Click Undo to bring the commits back, but uncommitted edits are gone for good.
  • You pushed already. Undo and reset only change your copy. If others may have pulled the commit, use Revert. If you reset a pushed branch, pushing the result needs a force push, which replaces the remote copy (the Push dialog offers Force push when your branch and the remote have diverged). Do that only on a branch nobody else uses.
  • Undo did more than you expected. The dialog always shows the last action first. If it is not the one you meant, click Cancel and use Reset to here… on the exact commit instead.
  • The undo arrow does nothing. canopy ignores the shortcut while you are typing in a text box, and ignores it while another action is still running. Click the arrow, or wait for the action to finish.
