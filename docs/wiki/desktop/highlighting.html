Syntax highlighting and live refresh

How canopy desktop colors code in diffs and notices changes as you make them.

Two things in canopy desktop happen without you asking: code in diffs is colored by language, and the pages update themselves when files or branches change. This page explains what each one covers and where the limits are.

Syntax highlighting#

Diffs on the Changes, History and Stash pages are colored by language: keywords, strings, comments, numbers and so on. The green and red backgrounds for added and removed lines stay; the syntax colors sit on top of them. The colors come from your theme, so they follow it when you switch.

  • Always on. The desktop app has no setting to turn highlighting off. (canopy console does: see its highlighting page.)
  • Unknown languages stay plain. A file type canopy doesn't recognise, and binary files, show without syntax colors. The diff still works.
  • Both sides are read separately. The old version and the new version of a file are each colored on their own, so a change that starts inside a string or comment still looks right.

Limits#

Coloring very large diffs would make the app slow, so canopy skips it when it would cost too much. The diff is still shown in full, just without syntax colors.

LimitValueWhat happens past it
Line length2,000 charactersThat line is shown plain (minified files are the usual cause).
Hunk size5,000 linesThat whole hunk is shown plain.

Live refresh#

You don't have to press refresh after you save a file in your editor, switch branches in a terminal or commit from another tool. canopy watches the repository and updates the page you're on. It reacts to:

  • Files in your working folder, except ones git ignores (build output and the like, see ignore files).
  • Git's own state: the current branch, the staging area, branches and tags, and a merge, rebase, cherry-pick or revert in progress.

It waits about a quarter of a second after the last change so a burst of saves (a build, a branch switch) causes one update, not fifty. The update is quiet: the page redraws in place without a spinner and without losing your selection. Git's temporary lock files and internal object files are ignored, so a running git command doesn't trigger a refresh loop.

Refresh timer and window focus#

Two more refreshes back this up, for changes the watcher can't see, such as a push from another computer or a new pull request:

  • When you come back to the window. Switching to canopy from another app refreshes it.
  • On a timer. Set it in Settings under Refresh: 2s, 5s (the default), 15s, 1m or Off. The timer only runs while the window is visible.
Off doesn't turn off live refresh. The Refresh setting only controls the timer. The instant updates from the file watcher and the refresh on window focus stay on. Press ⌘R (Ctrl+R on Windows and Linux) any time to refresh by hand.

If something goes wrong#

  • A diff has no colors. Check the limits above (a very long line or a huge hunk), or the file type may not be one canopy recognises. The changes themselves are correct either way.
  • A change doesn't show up. If git ignores the file, canopy doesn't show it. Otherwise press ⌘R. If that fixes it, see "The page didn't update" in troubleshooting.
  • The app feels busy. Set Refresh to 15s, 1m or Off in Settings. Live updates from the file watcher still work.
