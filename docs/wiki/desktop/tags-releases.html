Tag a version and publish a release

Mark a commit as v1.2.0, push the tag, and publish a GitHub release with notes.

A tag is a permanent name for one commit, such as v1.2.0. Unlike a branch, it never moves. People use tags to mark the exact code that shipped, so they can come back to it later.

canopy desktop can create a tag, push it to your remote, check it out and delete it. It cannot create a GitHub release: that part happens on github.com, after the tag is pushed.

Tag or release?#

ThingWhat it isWhere you make it
TagA name on one commit. Part of your git history, so it travels with the repository.canopy desktop (History page)
ReleaseA GitHub page built on a tag, with notes and downloads.github.com, on the tag you pushed
Lightweight or annotated. If you leave the message empty, canopy makes a lightweight tag: just a name on a commit. If you type a message, it makes an annotated tag, which also records who tagged it, when, and your message. Annotated tags are the usual choice for versions you ship.

In canopy desktop#

  1. Open History in the sidebar and click the commit you want to mark. Its details open on the right.
  2. Click Tag…. A dialog titled "Tag" and the commit's short id opens.
  3. Type a Tag name, such as v1.2.0. Add a message in Message (leave empty for a lightweight tag) if you want an annotated tag, then click Create tag. A toast confirms "Tagged … as v1.2.0", and the tag shows as a chip on that commit.
  4. Open Branches and choose the Tags tab. Each tag lists its name, the commit subject and its age.
  5. Click Push on the tag row to send it to your remote. This button only shows when the repository has a remote. The toast reads "Pushed tag v1.2.0 to origin".
  6. To publish a release, open the pushed tag on GitHub in your browser and create the release from it, with your notes. canopy desktop has no release button.

The other buttons on a tag#

  • Check out switches your working folder to that tag's code. Git puts you in a "detached HEAD" state, which means you are not on a branch. Look around, then switch back to a branch on the Branches page. Don't commit there without making a branch first (New branch here… in History does that).
  • Delete asks "Delete tag …?" and says: "Deletes it here only; a pushed tag stays on the remote." The tag on your remote is not touched.

What git runs#

Pushing goes to origin, or to the first remote if there is no origin. The releases step happens on GitHub, so no command appears for it.

$ git tag v1.2.0 <commit>
$ git tag -a v1.2.0 -m "what changed" <commit>
$ git push origin v1.2.0
$ git tag -d v1.2.0

The first line is used when the message is empty, the second when you typed one. Check out runs git switch v1.2.0.

If something goes wrong#

  • The tag name already exists. Git refuses to reuse a tag name. Pick a new name, such as v1.2.1, or delete the old tag first on the Tags tab.
  • There is no Push button. The repository has no remote yet. Connect one first (see Start a new repository, or Sync with a remote).
  • You tagged the wrong commit, and it was not pushed yet. Delete it on the Tags tab, then tag the right commit from History. Nothing else is affected.
  • You tagged the wrong commit, and you already pushed it. Delete only removes the tag on your computer. Delete it on GitHub too (the repository's tags list), then delete it here and push the corrected tag. If others may have fetched the old one, use a new name instead.
  • The release shows the wrong code. A release belongs to a tag, and a tag belongs to one commit. Check which commit the tag points at in History. If it is wrong, replace the tag as above, then recreate the release on GitHub.
  • You checked out a tag and your commits seem to vanish. You were in a detached HEAD. Read Undo a mistake to get them back.
