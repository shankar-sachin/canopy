Write good commits

Small, focused commits with clear messages, and how to stage exactly the lines that belong together.

A commit saves a snapshot of what you have staged, together with a message that says why. This page covers writing the message, choosing exactly what goes into a commit, and where to fix one you have just made.

If the words working tree, staging area and commit are new, read Git in ten minutes first.

In canopy desktop#

Write a good message#

  • Summary: one short line, about 50 characters. Say what the change does: "Ignore case when counting words".
  • Description (optional): why you did it, or what a reader might miss. canopy puts a blank line between the two for you.
  • Say why, not just what. "Fix crash on an empty file" beats "update main.rs".
Only commit related changes together. If a summary needs the word "and", you probably have two commits. Staging single lines or blocks, below, is how you split them.

Choose what goes in#

  1. Open Changes (⌘2 (Ctrl+2 on Windows and Linux)). Changed files are listed under Changes. Files already staged are under Staged.
  2. To stage a whole file, click the + beside it, or select it and press space. Stage all stages everything. Unstage all, or the − beside a file, takes things back out.
  3. To stage only part of a file, select it and look at the diff. Click a + or − line to pick it (shift-click picks a range), then press Stage N lines. Or press Stage hunk above a block of changes to stage the whole block. For a staged file, Unstage N lines and Unstage hunk take pieces back out.
  4. The file's own buttons are Stage file (or Unstage file), Discard… and Open in editor. Discard… throws away your unstaged edits to that file for good, so it asks first.

Make the commit#

  1. Type a Summary (required) in the commit box, and a Description if it helps.
  2. Press Commit N files, or ⌘↵ (Ctrl+Enter on Windows and Linux). If nothing is staged, the button reads Stage all & commit and stages every change first.
  3. To change the commit you just made instead, tick Amend last commit; the button becomes Amend. See Fix your last commit.

An empty summary shows "Write a short summary of what changed first." and nothing is committed. canopy desktop does not count characters, so keep the summary short yourself. With Show git commands on in Settings, each action shows the git command it ran.

What git runs#

Staging and committing are a few plain commands. Staging lines or a block builds a small patch and applies it to the staging area only, so your files are not touched.

$ git add -- src/main.rs
$ git add --all
$ git restore --staged -- src/main.rs
$ git apply --cached --unidiff-zero --whitespace=nowarn -
$ git commit -m "Ignore case when counting words"
$ git commit -m "Ignore case when counting words" --amend

Un-staging lines uses the same git apply --cached with --reverse. A description is added to the message after a blank line.

If something goes wrong#

  • The commit box says "Nothing to commit". There are no changes, or you have not saved your files. Save in your editor and try again.
  • You committed too much or too little. If you have not pushed, amend it (Fix your last commit) or undo it with ⌘Z (Ctrl+Z on Windows and Linux). Your changes stay in your files, staged. See Undo a mistake.
  • You committed a file that should be ignored. See Ignore files with .gitignore.
  • Git says it does not know who you are. Set user.name and user.email with git config --global in a terminal, then commit again.
  • The commit is already pushed. Do not rewrite it. Make a new commit that fixes it, or see Undo a mistake.
