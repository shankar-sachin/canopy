Settings

Every setting in canopy desktop's Settings page, what it does, and its default.

Open Settings with the gear at the bottom of the sidebar, or with ⌘, (Ctrl+, on Windows and Linux). The gear is on the welcome screen too, so you can change things before you open a repository. Settings has four sections down the left: General, Appearance, Updates and About. Every change is saved as soon as you make it; there is no Save button (except when you make a theme, below).

The settings live in ~/.canopy/desktop.json, next to your recent repositories. Delete the file to go back to the defaults.

The editors canopy looks for are Visual Studio Code, Cursor, Zed, Sublime Text, Neovim, Vim, Helix, nano and Emacs. Editors that run in a terminal (Neovim, Vim, Helix, nano) open in a new terminal window. If none are found, the row says "No editors found on your PATH" and you can still use a custom command.

canopy console#

The end of General is about canopy console, the keyboard app:

  • If it isn't installed, a card shows the command that installs it on your system, with a Copy button. If it is, the card shows its version.
  • Suggest canopy console lets canopy mention it now and then, at most every two weeks and never in your first week. Turn it off and it never does. It is on by default, and only speaks up when canopy console isn't installed.
  • Share settings moves four settings between the two apps: the theme, the text editor, the AI assistant and Show git commands. Import from canopy console reads its config.toml; Send to canopy console writes into it, changing only those keys. If canopy console has no config yet, importing tells you so.
  • Settings file saves those same settings as a JSON file (Export…) for another computer or for canopy --import-settings, or loads one (Import…).

Appearance#

Pick a theme by clicking its card. Auto follows your computer's light or dark setting. The built-in themes are canopy (dark), canopy light, catppuccin, gruvbox and nord. Themes you made appear under Your themes.

  • Customize… (or Edit… for a theme of your own) opens the editor: a name, and a color picker plus hex box for each color, grouped as Base, Highlights, Changes and Git. The app changes as you pick, and a small preview of canopy console shows the colors that only appear there. Save theme stores only the colors that differ from the theme you started from.
  • Edit JSON (for a theme of your own) opens the selected theme's file in your text editor. Save the file and come back; canopy picks up the change.
  • Export… and Import… move a theme file in and out.
  • Delete asks first, then removes the file. Both apps lose the theme, because they share the folder.

Themes are JSON files in ~/.canopy/themes/, and canopy console reads the same ones. The themes page shows every built-in theme and explains the file.

Updates#

  • Check automatically looks once a day, when canopy starts. It only asks GitHub for the latest version number; nothing else is sent. On by default.
  • Check now looks straight away. The Version row says how your copy was installed: Homebrew, winget, the .deb package, an AppImage, or built from source or by hand.
  • When a newer version exists, a dot appears next to Updates, and the section shows the update command: brew upgrade --cask canopy-desktop for Homebrew, winget upgrade shankars.canopy-desktop for winget. For the other install types it points you to the release page instead. What's new opens the release notes.

About#

The version, and buttons for the website, this wiki, the source code and Report a problem. It also lists the main shortcuts (see keyboard shortcuts).

Your GitHub account#

The avatar and name at the bottom of the sidebar open a separate panel, not part of Settings. It shows which GitHub account the GitHub CLI is logged in as, where its token is stored, which git protocol it uses, and its permissions; your git name and email; and the versions of git and gh it found. canopy never sees your token. To switch accounts or sign out, run gh auth login or gh auth logout in a terminal, then press Check again. If git doesn't know your name and email yet, the panel shows the two git config --global commands to set them.

If something goes wrong#

  • A setting didn't stick. A red message says "Couldn't save settings" and why, usually that the ~/.canopy folder can't be written to. Fix the folder's permissions and try again.
  • The editor doesn't open. A red "Couldn't open the editor" message says why. Pick System default, or check that your custom command runs in a terminal.
  • Fix with AI does nothing. Check the AI assistant row shows one found, and see troubleshooting for the macOS Terminal permission.
  • Settings look wrong after an import. Import only changes the four shared settings. To start over, delete ~/.canopy/desktop.json while canopy is closed.
