Git in ten minutes

The handful of ideas that make git make sense, and where to see each one in canopy.

These few ideas are all of git you need to get going. They're the same in canopy desktop and canopy console: each section says where to see the idea in both apps, and links to the full guide for each.

A repository is a project with a memory#

A repository (repo) is a folder whose history git tracks. Everything git knows lives in a hidden .git folder inside it. Open a repo in canopy desktop, or run canopy in it, and Home shows where things stand (⌘1 in canopy desktop, 1 in canopy console).

Your changes live in three places#

  • The working tree is the files you edit. Changes here are listed under Changes on the Changes page (⌘2 in canopy desktop, 2 in canopy console).
  • The staging area (also called the index) is where you gather what goes into the next commit. Staged files appear under Staged.
  • History is the commits themselves, on the History page (⌘3 in canopy desktop, 3 in canopy console).

Staging is what lets you commit part of your work. In canopy desktop you can stage a whole file with its + button, or click lines in its diff and press Stage N lines. In canopy console, stage a file with space, or step into its diff with ↵ and stage single lines. See Write good commits (desktop) or the same page for console.

A commit is a saved snapshot#

A commit records the staged changes with a message saying why. Each commit points to the one before it, which is how history forms a chain. In canopy desktop, write a summary in the commit box and press Commit. In canopy console, press c, write a short summary (a counter runs up to 50 characters), and press ↵.

Good messages say why: "Fix crash when the repo has no commits" beats "update main.rs".

A branch is a line of work#

A branch is a movable name for a commit. When you commit, your current branch moves forward. Branches let you try something without disturbing main. The Branches page lists them: New branch… and Check out in canopy desktop, 4 then n and space in canopy console. See Branches, merging and rebasing (desktop) or the console version. HEAD means "where you are now"; History shows it as HEAD → main.

A remote is the same repo somewhere else#

A remote (usually called origin) is a copy of the repo on a server such as GitHub. Push sends your commits there; pull brings others' commits to you; fetch checks what's new without changing your files. Each is a button in canopy desktop's top bar, and P, p and f in canopy console. canopy shows ↑2 ↓1 when you're 2 commits ahead and 1 behind. See Sync with a remote (desktop) or the console version.

You can almost always undo#

Git rarely forgets anything. Undo takes back your last commit, reset, merge or checkout: ⌘Z (Ctrl+Z on Windows and Linux) in canopy desktop, z in canopy console. canopy console's Reflog tab (7) lists everywhere you've been so you can go back further. See Undo a mistake (desktop) or the console version.

Learn as you go: canopy console's teach mode is on by default and shows the git command behind every action in the footer. canopy desktop does the same with Show git commands in Settings. The ideas on this page turn into commands you'll recognize.
